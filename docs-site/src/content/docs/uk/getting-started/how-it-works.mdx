Codex спілкується протоколом OpenAI **Responses API**. opencodex приймає `POST /v1/responses` по HTTP
із Server-Sent Events, а також опційно підтримує WebSocket upgrade на тому самому шляху. Він перекладає
запит у мережевий формат вашого провайдера, а відповідь — назад в події Responses, тож Codex навіть не
здогадується, що спілкується не з OpenAI.

```
            ┌──────────────────────────── opencodex ────────────────────────────┐
            │                                                                     │
 Codex ──▶  │  parser ──▶ router ──▶ [vision] ──▶ adapter ──▶ provider           │  ──▶ Codex
 (/v1/      │     │          │          │            │           │                │   (SSE / WS)
  responses)│   OcxParsed  provider   describe    buildRequest  parseStream       │
            │   Request    +adapter   images       + fetch      AdapterEvent[]    │
            │                                          │           │              │
            │                                  [web-search loop]  bridge ─▶ SSE   │
            └─────────────────────────────────────────────────────────────────────┘
```

## Вибір акаунта Codex auth

Коли вибраний провайдер — це наскрізний ChatGPT/Codex, opencodex може вибрати збережений акаунт пулу
перед тим, як запит буде перенаправлено на вихідний провайдер. Правило навмисно розділене:

- **Наявні ідентифікатори тредів зберігають афінність.** Тред прив'язаний до покоління акаунта, що його
  почало, тож тривала сесія Codex через SSH, tmux або з мобільного продовжує використовувати один
  акаунт, а не перебалансовується посеред розмови.
- **Нові сесії можуть перебалансовуватися.** Для нового треда opencodex порівнює відоме використання
  квоти у вікнах 5 год, тижневому й 30-денному, пропускає акаунти, що потребують повторної
  автентифікації або перебувають у кулдауні, і може перемкнутися на прийнятний акаунт із меншим
  використанням, коли активний акаунт перетне налаштований поріг.
- **Сигнали квоти й збоїв живлять маршрутизацію.** Панель може примусово оновити квоту через
  `GET /api/codex-auth/accounts?refresh=1`; успішні відповіді з боку вихідного провайдера захоплюють
  заголовки квоти, 429 переводить акаунт у кулдаун, а 401/403 позначає його для повторної
  автентифікації.

## Вибір моделі субагента

При свіжому встановленні `subagentModels` виводить `gpt-5.5`, трійку GPT-5.6 Sol/Terra/Luna та
`gpt-5.4-mini` у селекторі субагентів Codex. Панель може переупорядкувати чи замінити до п'яти записів
нативними або маршрутизованими моделями. Для запитів співпраці v1 опційні налаштування `injectionModel`
та `injectionEffort` додають настанову розробника, яка вказує `spawn_agent`, яку модель та зусилля
міркувань використовувати; запити v2 зберігають нативну мультиагентну настанову Codex.

## Життєвий цикл

<Steps>

1. **Parse** — `responses/parser.ts` валідує запит за схемою Zod (`responses/schema.ts`) і зводить
   його до внутрішнього `OcxParsedRequest`: системний промпт, нормалізований список повідомлень
   (текст, зображення, виклики інструментів, результати інструментів), визначення інструментів, опції
   генерації та прапорці функцій, як-от `_webSearch` (запитано хостований вебпошук) та
   `_structuredOutput` (задано JSON-схему / JSON-об'єкт `text.format`). Зображення зберігаються як
   справжні частини контенту — ніколи не вбудовуються як base64-текст.

2. **Route** — `router.ts` зіставляє запитаний ідентифікатор моделі з налаштованим провайдером за
   фіксованим пріоритетом: явний `provider/model` → `defaultModel` провайдера → вбудовані шаблони
   префіксів (`claude-`, `gpt-`, `o1-`/`o3-`/`o4-`, `llama-`/`mixtral-`/`gemma-`) → `models[]`
   провайдера → резервний `defaultProvider`. Див. [Маршрутизація моделей](/opencodex/uk/guides/model-routing/).

3. **Authenticate** — для провайдера `oauth` opencodex підставляє свіжий, автооновлений токен доступу
   як bearer-ключ, тож наявні адаптери автентифікуються без змін. Для акаунтів пулу ChatGPT/Codex
   `codex/auth-context.ts` спершу визначає акаунт, і наскрізний адаптер відмовляється продовжувати,
   якщо потрібні облікові дані пулу недоступні.

4. **Sidecar зору (опційно)** — якщо маршрутизована модель є в `provider.noVisionModels`, а запит несе
   зображення, opencodex описує кожне зображення налаштованим sidecar-ом зору ChatGPT і замінює його
   текстом, тож текстова модель усе одно може над ним міркувати. Див. [Сайдкари](/opencodex/uk/guides/sidecars/).

5. **Швидкий шлях наскрізної передачі** — якщо адаптер є наскрізним Responses (`openai-responses` або
   `azure-openai`), opencodex зберігає тіло Responses, застосовує цільові перезаписи маршрутизації й
   сумісності, а потім ретранслює відповідь провайдера, не конвертуючи її через `AdapterEvent`-и.

6. **Sidecar вебпошуку (опційно)** — якщо Codex увімкнув хостований `web_search`, але маршрутизована
   модель — не від OpenAI, opencodex надає синтетичний функціональний інструмент `web_search` і
   запускає модель у невеликому агентному циклі, виконуючи справжні пошуки через `gpt-5.6-luna` за
   замовчуванням поверх вашого входу в ChatGPT та впроваджуючи результати назад як результати
   інструментів.

7. **Compact (за запитом)** — Codex v1 викликає `POST /v1/responses/compact`; v2 додає
   `compaction_trigger` до ходу Responses. Нативна наскрізна передача маршрутизує компакцію на вихідний
   провайдер, тоді як маршрутизована модель працює як summarizer без інструментів і повертає форму
   заміни історії, яку очікує Codex.

8. **Adapt** — інакше `buildRequest()` вибраного адаптера створює вихідний HTTP-запит (URL, заголовки,
   тіло) у нативному форматі провайдера, і opencodex виконує його `fetch`.

9. **Bridge** — `parseStream()` (або `parseResponse()`) адаптера видає внутрішні `AdapterEvent`-и
   (text, reasoning, tool-call start/delta/end, done, error). `bridge.ts` конвертує цей потік назад у
   події Responses SSE — `response.output_text.delta`, `response.reasoning_summary_text.delta`,
   `response.function_call_arguments.delta`, `response.completed` тощо. Опційний транспорт WebSocket
   надсилає ті самі корисні навантаження подій як текстові фрейми.

</Steps>

## Чому проксі, а не форк Codex?

Codex жорстко зашиває Responses API. Перекладаючи на межі протоколу, opencodex працює з **CLI, App і
SDK** Codex без змін, переживає оновлення Codex і дає змогу перемикати провайдерів на кожен запит, не
чіпаючи сам Codex. Переклад двонаправлений і точний щодо стрімінгу: резюме міркувань, простори імен
інструментів MCP, вільні (`apply_patch`) інструменти та виявлення `tool_search` — усе коректно
проходить в обидва боки. Див. [Довідник з архітектури](/opencodex/uk/reference/architecture/) для
відображення подія за подією.
