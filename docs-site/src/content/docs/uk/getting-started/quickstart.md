Цей посібник проведе вас від свіжого встановлення до запуску Codex на моделі не від OpenAI.

## 1. Запустіть майстер налаштування

```bash
ocx init
```

`ocx init` проведе вас через:

1. **Вибір провайдера** — оберіть один із 50 вбудованих пресетів реєстру або `custom`, щоб ввести
   base URL та адаптер.
2. **API-ключ** — вставте ключ або вкажіть змінну середовища, як-от `${ANTHROPIC_API_KEY}`.
3. **Модель за замовчуванням** — для провайдерів із ключем, локальних і власних прийміть пресет або
   введіть ідентифікатор моделі.
4. **Порт проксі** — за замовчуванням `10100`.
5. **Інтегрувати в Codex?** — при звичайному loopback-налаштуванні opencodex додає кореневий
   `openai_base_url` у `$CODEX_HOME/config.toml` (за замовчуванням `~/.codex/config.toml`), щоб
   вбудований провайдер `openai` у Codex вказував на проксі. Віддалені/LAN-прив'язки натомість
   використовують окремий запис провайдера із заголовком API-автентифікації.
6. **Встановити shim автозапуску?** — коли ввімкнено, запуск `codex` спершу виконує `ocx ensure`.

Результат зберігається у `$OPENCODEX_HOME/config.json` (за замовчуванням `~/.opencodex/config.json`).

:::note[Записи розгортання GPT-5.6]
Стабільна v2.7.1 додає GPT-5.6 Sol/Terra/Luna для наскрізного ChatGPT, OpenAI API-ключа, OpenRouter та
експериментального адаптера Cursor. Вони працюють лише тоді, коли цей акаунт з боку вихідного
провайдера має доступ. Пресети OpenAI API-ключа та OpenRouter оголошують корисне вікно контексту
372 000 токенів; Cursor зберігає власні метадані адаптера.
:::

## 2. Запустіть проксі

```bash
ocx start            # за замовчуванням порт 10100
ocx start --port 8080
```

Під час запуску opencodex:

- записує свій PID у `~/.opencodex/ocx.pid` (і відмовляється стартувати двічі),
- виявляє живі моделі там, де провайдер це підтримує, і **синхронізує нативні та маршрутизовані
  записи в каталог моделей Codex**,
- слухає на `http://localhost:<port>/v1`.

Якщо запитаний порт зайнятий, `ocx start` вибирає вільний порт, записує його в `runtime-port.json` і
оновлює Codex, щоб він використовував живий слухач.

Перевірте:

```bash
ocx status
ocx gui       # відкрити панель на живому порту
```

## 3. Використовуйте Codex

Codex тепер прозоро спілкується з opencodex:

```bash
codex "Refactor this function for readability"
```

Щоб звернутися до конкретної маршрутизованої моделі, використайте форму `provider/model`, яку показує
селектор моделей Codex:

```bash
codex -m "anthropic/claude-opus-5" "Explain this stack trace"
codex -m "ollama-cloud/glm-5.2"      "Write a SQL migration"
```

## Виберіть моделі субагентів (опційно)

Свіжий конфіг виводить п'ять нативних моделей у селекторі субагентів Codex: `gpt-5.5`,
`gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` та `gpt-5.4-mini`. Відкрийте `ocx gui`, щоб замінити чи
переупорядкувати до п'яти нативних або маршрутизованих моделей. Панель також може задати одну бажану
модель субагента й зусилля міркувань; opencodex додає цю настанову до запитів співпраці v1.

## Вхід замість вставляння ключа

Деякі провайдери підтримують справжній вхід в акаунт (OAuth, з автооновленням):

```bash
ocx login xai          # або: anthropic, kimi, kiro, google-antigravity, cursor
ocx logout xai
```

Самому OpenAI **ключ не потрібен** — провайдер за замовчуванням наскрізно перенаправляє ваші наявні
облікові дані `codex login` (див. [Провайдери](/opencodex/uk/guides/providers/)).

## Зупинка й відновлення

```bash
ocx stop          # зупинити проксі та відновити нативний Codex
ocx restore       # відновити нативний Codex без зупинки (аліас: ocx eject)
ocx restore back  # знову спрямувати Codex через ще запущений проксі
```
