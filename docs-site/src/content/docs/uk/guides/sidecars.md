Не всі маршрутизовані моделі надають хостований **вебпошук** чи нативний **ввід зображень**. opencodex
доповнює ці можливості двома sidecar-ами. Кожен може працювати через провайдера з входом ChatGPT
(`forward`) або збереженого провайдера Anthropic OAuth. Помилки sidecar-а стають обмеженими
результатами інструментів або маркерами зображень замість того, щоб провалити весь хід.

:::note[Автоматичний вибір бекенда]
Явна конфігурація `backend` має пріоритет. Коли її не задано, opencodex використовує `anthropic`, якщо
ввімкнений провайдер Anthropic OAuth має активний акаунт, не позначений `needsReauth`; інакше —
`openai`. Явний `anthropic` без цих облікових даних «падає закрито». `openai` потребує і автентифікації
входу ChatGPT, і ввімкненого провайдера `forward`.
:::

## Sidecar вебпошуку

Коли Codex запитує хостований `web_search` для не-наскрізної маршрутизованої моделі, opencodex:

1. **Прибирає** хостований інструмент `web_search` і натомість надає маршрутизованій моделі синтетичний
   функціональний інструмент `web_search(query)`. Оригінальні опції хостованого інструмента
   зберігаються для виклику sidecar-а.
2. Запускає маршрутизовану модель у невеликому **агентному циклі**. Коли вона викликає `web_search`,
   opencodex використовує вибраний бекенд sidecar-а: OpenAI запускає хостований `web_search` з
   `gpt-5.6-luna` за замовчуванням; Anthropic запускає `web_search_20250305` з `claude-sonnet-5` за
   замовчуванням. Потокова відповідь і цитати стають результатом інструмента.
3. **Повторює цикл**, доки модель не відповість або загальний бюджет справжніх запитів не досягне
   `maxSearchesPerTurn` (за замовчуванням 3), потім прибирає інструмент пошуку й змушує дати остаточну
   відповідь. Справжні клієнтські інструменти, як-от `apply_patch` чи shell, завершують хід, тож ці
   виклики доходять до Codex.

Кожна ітерація маршрутизованої моделі запитує вихідний `stream: true`, але opencodex повністю буферизує
семантичні події внутрішньо, перш ніж вирішити, шукати чи повернути остаточну відповідь. Лише остаточні
заголовки/статус першої ітерації та ротації ключів на 429 отримуються завчасно. Тож синтетичні виклики
пошуку й попередній вивід ніколи не показуються як видимий клієнту вивід моделі.

Впроваджений результат обгортається межею недовірених даних, обмежується за довжиною й дедуплікується
за URL джерела. У ходах зі структурованим виводом (`json_schema` / `json_object`) він передається як
компактний JSON замість прози. Для текстових маршрутизованих моделей моделі пошуку також вказується
описувати релевантні зображення словами й включати їхні URL джерел.

```json
{
  "webSearchSidecar": {
    "enabled": true,
    "backend": "anthropic",
    "model": "claude-sonnet-5",
    "reasoning": "low",
    "maxSearchesPerTurn": 3,
    "routedModelStallTimeoutMs": 200000,
    "timeoutMs": 200000
  }
}
```

Міркування `minimal` не використовуються, бо хостований бекенд відхиляє інструменти на цьому зусиллі.
Невдалий пошук повертається маршрутизованій моделі як обмежений результат-помилка, що дозволяє їй
відповісти з контексту, який вона вже має.

Застосовуються чотири окремі годинники. `stallTimeoutSec` — це базовий бюджет застою подій мосту.
`connectTimeoutMs` (за замовчуванням `200000`) покриває лише DNS/TCP/TLS та остаточні заголовки
відповіді. Лише-конфіговий `webSearchSidecar.routedModelStallTimeoutMs` (за замовчуванням `200000`,
ціле `1..2147483647`) обмежує безперервну неактивність сирих байтів відповіді для кожної ітерації
маршрутизованої моделі й скидається на кожному непорожньому байті. `webSearchSidecar.timeoutMs` окремо
обмежує один хостований запит пошуку. Ефективний watchdog мосту —
`max(базовий застій, таймаут з'єднання, застій маршрутизованої моделі, таймаут sidecar-а) + 30 секунд`.
Застій маршрутизованої моделі — це не загальний таймаут генерації. Збої до старту SSE повертають
не-2xx JSON; збої генерації після того, як заголовки відповіді почалися, доставляються як
`response.failed` SSE.

## Sidecar зору

Коли маршрутизована модель є в `noVisionModels` свого провайдера, а запит несе зображення, opencodex
описує кожне зображення **перед** основним викликом і замінює його текстом. Панель та управлінський API
показують `gpt-5.6-luna` як поточний варіант за замовчуванням, а запуск мігрує явно збережене застаріле
значення `gpt-5.4-mini` на Luna. Якщо поле `visionSidecar.model` цілком відсутнє, шлях виконання зору
все одно має кодовий резерв `gpt-5.4-mini`.

- Зображення можуть надходити з повідомлень користувача, розробника й результатів інструментів,
  зокрема з `view_image` у Codex.
- Кожне зображення надсилається налаштованій нативній моделі зору з `reasoning.effort: "low"`; його опис
  замінює частину зображення inline.
- Описи виконуються з обмеженою конкурентністю (по 3 одночасно, порядок вводу збережено). Контекст
  користувача, надісланий описувачу, обмежено 800 символами, а кожен впроваджений опис — 2000 символами.
  Запит не надсилає `max_output_tokens`, який бекенд ChatGPT відхиляє.
- URL зображень валідуються перед перенаправленням: data URL мають використовувати `png` / `jpeg` /
  `jpg` / `webp` / `gif`, а base64-дані обмежені приблизно 20 МБ. Приймаються лише схеми `data:` та
  `https:`; віддалені `https`-зображення завантажує бекенд OpenAI, а не проксі.
- Зіставлення `noVisionModels` ігнорує суфікс `:size` у стилі Ollama, тож запис `gpt-oss` також покриває
  `gpt-oss:120b`.
- Якщо опис зазнає невдачі, модель отримує короткий маркер помилки обробки. Якщо план sidecar-а
  недоступний, сире зображення прибирається, а не перенаправляється текстовому бекенду.
- `maxDescriptionsPerTurn` (за замовчуванням 8) обмежує нові описи на хід основної моделі. Влучання в
  кеш і дублікати в межах того самого ходу його не витрачають. Успішні описи `data:`-зображень
  кешуються за бекендом, моделлю, деталізацією, байтами зображення й контекстом повідомлення; змінні
  `https:`-зображення не кешуються.

```json
{
  "visionSidecar": {
    "enabled": true,
    "backend": "anthropic",
    "model": "claude-sonnet-5",
    "maxDescriptionsPerTurn": 8,
    "timeoutMs": 45000
  }
}
```

Модель позначається як текстова для кожного провайдера:

```json
{
  "providers": {
    "ollama-cloud": {
      "adapter": "openai-chat",
      "baseUrl": "https://ollama.com/v1",
      "noVisionModels": ["glm-5.2", "gpt-oss", "qwen3-coder", "deepseek-v4-pro"]
    }
  }
}
```

## Елементи керування панелі та вимкнення

<!-- TODO(WP5 GUI): Add the sidecar settings-screen walkthrough after the GUI controls ship. -->

Конфігові ключі доступні вже зараз. Встановіть `enabled: false` для будь-якого sidecar-а в
`config.json`, щоб його вимкнути. Пошук через Anthropic-OAuth та опис зображень повторно використовують
наявний прецедент OAuth-фінгерпринта Claude Code, але їх варто протестувати під навантаженням із
призначеним акаунтом і робочим навантаженням.
