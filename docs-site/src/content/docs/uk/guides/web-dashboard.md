opencodex постачає локальну веб-панель (застосунок Vite/React під `gui/`), що обслуговується з проксі.
Це найкоротший шлях до керування провайдерами, акаунтами Codex/ChatGPT, моделями каталогу, sidecar-ами,
налаштуваннями субагентів та трафіком запитів.

## Відкриття

```bash
ocx gui
```

Це відкриває `http://localhost:<port>` у вашому браузері, спершу автоматично запускаючи проксі за
потреби. У розробці ви можете запустити dev-сервер GUI окремо проти запущеного проксі:

```bash
ocx start
bun run dev:gui
```

## Що можна робити

| Область | Що робить |
| --- | --- |
| **Зведення панелі** | Режим мультиагента, стан онлайн, версія, аптайм, кількість провайдерів, підсумок токенів за 30 днів, активні провайдери та доступні нативні/маршрутизовані моделі. |
| **Делегування субагентів** | Виберіть нативну чи маршрутизовану модель настанови й опційне зусилля міркувань для промптів делегування v1. Це не роутер на кожне породження; див. нижче. |
| **Сайдкари** | Виберіть модель і зусилля вебпошуку плюс модель опису зображень. Зміни застосовуються на наступний запит. |
| **Обслуговування** | Повторно синхронізуйте каталог моделей Codex, перегляньте попередження про обхід локального конфіга проєкту, перевірте останній чи preview-реліз і запустіть оновлення з опційним перезапуском проксі. |
| **Безпека запуску** | Показує, чи переживає впроваджена маршрутизація Codex перезапуск, з окремим станом служби та лаунчер-shim і точними командами ремонту. |
| **Трей Windows** | Встановіть трей входу для кожного користувача для запуску, зупинки, перезапуску проксі одним кліком, доступу до панелі та статусу. Трей — це контролер, а не служба перезапуску проксі. |
| **Автозапуск Codex** | Дозволяє вже встановленому лаунчер-shim Codex виконувати `ocx ensure`. Цей перемикач не встановлює shim чи фонову службу. |
| **Провайдери** | Додавайте, редагуйте, вмикайте/вимикайте та вилучайте провайдерів; керуйте пулами акаунтів OAuth і пулами API-ключів там, де підтримується. Налаштування провайдера можуть вимкнути живе виявлення моделей для ендпоінтів із відсутніми, повільними чи завеликими каталогами `/models`. |
| **Додати провайдера** | Шукайте пресети з реєстру для входу в акаунт, сервісів з API-ключем, локальних серверів або власного ендпоінта. |
| **Codex Auth** | Додавайте акаунти пулу ChatGPT/Codex, вибирайте акаунт наступної сесії, оновлюйте квоти 5 год / тижня / 30 днів і налаштовуйте автоперемикання за квотою й фейловер за тимчасовими збоями. |
| **Субагенти** | Виведіть до п'яти звичайних нативних або маршрутизованих моделей із простором імен у списку перевизначень `spawn_agent`. |
| **Моделі** | Перемикайте нативні GPT та маршрутизовані моделі, задавайте allowlist-и провайдерів та обмеження контексту, вибирайте v1/base/v2 і налаштовуйте ліміт тредів v2. Налаштовані провайдери залишаються видимими як групи з нуля моделей, коли виявлення вимкнено або не повертає рядків. |
| **Журнали** | Автооновлення нещодавніх запитів із токенами, запитаним зусиллям, розв'язаною моделлю, провайдером, статусом, ідентифікатором запиту, тривалістю та деталями помилок. |
| **Використання / Debug** | Перегляньте покриття й тренди використання токенів або ввімкніть опційну діагностику транспорту провайдера та вилучення використання. |
| **Зупинка** | Плавно зупиніть проксі та встановлену фонову службу, відновіть нативний Codex і вийдіть (`POST /api/stop`). |

Значення вартості в **Журналах** та **Використанні** — це еквіваленти прейскурантних API-цін,
обчислені зі звітованих токенів. Це не платіжні квитанції й не докази фактичного списання; натомість
можуть застосовуватися використання за підпискою або кредити провайдера.

## Селектор делегування проти маршрутизації породження

Селектор **Делегування субагентів** у панелі зберігає `injectionModel` та, опційно, `injectionEffort`.
На ході v1 opencodex впроваджує настанову, що вказує батьківському агенту, яку саме модель і зусилля
міркувань передати в `spawn_agent`. Вибір моделі вмикає цю настанову на будь-якому зусиллі міркувань
батька; очищення моделі також очищає збережене зусилля.

:::caution
Цей селектор — це настанова з делегування для інтерфейсу сумісності v1. На `multi_agent_v2` поточний
проксі не додає повідомлення впровадження v1, і кожен породжений субагент успадковує модель
батьківської сесії. Це не міжмодельний роутер на боці проксі. Див.
[Інтерфейс субагентів](/opencodex/uk/guides/sub-agent-surface/) щодо канонічної поведінки v1/base/v2.
:::

Селектор пропонує ввімкнені нативні й маршрутизовані моделі плюс глобальну драбину зусиль Codex. API
валідує вибране зусилля глобально; Codex усе одно валідує зусилля породження щодо цільового запису
каталогу.

## Codex Auth та пули акаунтів

Сторінка **Codex Auth** керує нативним маршрутом ChatGPT/Codex:

- Ручний вибір акаунта змінює наступну нову сесію Codex; уже прив'язаний тред зберігає свій поточний
  акаунт для цього ручного перемикання.
- Афінність тредів запобігає перемиканню на кожен запит. Із увімкненим автоперемиканням за квотою
  тривалий тред періодично переоцінюється й може перепривʼязатися після того, як його релевантне
  використання досягне порога та існуватиме прийнятний акаунт із суворо меншим використанням.
- Нові сесії можуть вибрати прийнятний акаунт із найменшим використанням. Платні плани оцінюють
  найзавантаженіше відоме вікно 5 год, тижня чи 30 днів; плани Go/Free використовують лише 30-денне
  вікно.
- Коли WHAM надає `limit_window_seconds`, Codex Auth класифікує основне вікно щонайменше 28 днів як
  30d замість припущення, що кожне основне вікно тижневе. Відповіді без тривалості зберігають застарілу
  тижневу інтерпретацію.
- **Оновити квоти** негайно перечитує використання акаунтів, тож маршрутизація й картки акаунтів
  використовують ті самі значення.
- Журнали запитів пулу використовують непрозорі мітки, як-от `p3fa91c`, ніколи не e-mail акаунтів.

## Як панель спілкується з проксі

GUI — це тонкий клієнт над JSON-управлінським API проксі. Корисні ендпоінти включають:

| Ендпоінт | Призначення |
| --- | --- |
| `GET` / `PUT /api/settings` | Прочитати налаштування або перемкнути автозапуск Codex. |
| `GET /api/startup-health` | Прочитати діагностику маршрутизації без секретів, служби, shim та безпеки перезапуску. |
| `POST /api/startup-action` | Встановити фонову службу або лаунчер-shim Codex через фіксовані дії з allowlist. |
| `GET` / `POST /api/windows-tray` | Прочитати чи змінити встановлення трею Windows та стан видимого процесу. POST приймає `install`, `start`, `stop` чи `uninstall`. |
| `POST /api/sync` | Перебудувати спільний каталог моделей і зробити застарілим кеш моделей Codex. |
| `GET /api/update/check` · `POST /api/update/run` · `GET /api/update/status` | Перевірити, запустити й відстежувати завдання самооновлення. |
| `GET` / `PUT /api/sidecar-settings` | Прочитати чи задати налаштування моделей sidecar-ів пошуку/зору. |
| `GET` / `PUT /api/injection-model` | Прочитати чи задати модель настанови делегування v1 та опційне зусилля. |
| `GET` / `PUT /api/v2` | Прочитати чи задати режим інтерфейсу, прапорець функції Codex та ліміт тредів v2. |
| `GET /api/providers` · `POST /api/providers` · `PATCH /api/providers?name=...` · `DELETE /api/providers?name=...` | Перелічити, додати/замінити, увімкнути/вимкнути чи вилучити провайдерів. |
| `GET /api/models` · `PUT /api/disabled-models` | Перелічити рядки нативних/маршрутизованих моделей та оновити спільний набір вимкнених моделей. |
| `GET /api/key-providers` · `GET /api/oauth/providers` | Прочитати каталоги провайдерів з API-ключем та OAuth. |
| `POST /api/oauth/login` · `GET /api/oauth/status` | Запустити OAuth-потік провайдера й опитувати завершення. |
| `GET /api/codex-auth/accounts?refresh=1` | Перелічити основний та пулові акаунти, примусово оновити квоту й повідомити стан `hasCredential` основного акаунта / термінальний `needsReauth`. |
| `PUT /api/codex-auth/active` · `PUT /api/codex-auth/auto-switch` · `PUT /api/codex-auth/failover` | Вибрати акаунт наступної сесії й налаштувати маршрутизацію пулу. |
| `POST /api/codex-auth/login` · `GET /api/codex-auth/login-status` | Додати пуловий акаунт через вхід у браузері. |
| `GET /api/logs?tail=50&provider=...&status=5xx` | Прочитати метадані нещодавніх запитів з опційними фільтрами tail, провайдера та точного/класового статусу. |
| `GET` / `PUT /api/subagent-models` | Прочитати чи задати п'ять виведених моделей перевизначення `spawn_agent`. |
| `POST /api/stop` | Зупинити проксі/службу, відновити нативний Codex і вийти. |

:::tip
Додавання **Ollama Cloud** чи іншого провайдера каталогу з панелі копіює його класифікацію
текст-проти-зору у збережений конфіг провайдера, тож [sidecar зору](/opencodex/uk/guides/sidecars/)
гейтиться коректно без ручної класифікації.
:::
