opencodex обслуговує `POST /v1/messages` (плюс `count_tokens`) поряд із `/v1/responses`, тож Claude
Code може використовувати кожного маршрутизованого провайдера — включно з входами OAuth, пулами
акаунтів, фейловером ключів і sidecar-ами — без жодної додаткової роботи з автентифікацією.

## Швидкий старт

```bash
ocx claude
```

`ocx claude` переконується, що проксі працює, потім запускає Claude Code з налаштованим середовищем:

| Змінна | Значення |
| --- | --- |
| `ANTHROPIC_BASE_URL` | `http://127.0.0.1:<port>` |
| `ANTHROPIC_AUTH_TOKEN` | Лише коли проксі потребує API-ключ — інакше вона НЕ встановлюється, тож ваш вхід у claude.ai (підписка + конектори) залишається активним |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` (нативне виявлення в селекторі `/model`) |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | Поріг автокомпакції контексту (за замовчуванням `350000`); впроваджується лише коли ввімкнено auto-context |
| `ANTHROPIC_MODEL` | `claudeCode.model` (опційно) |
| `ANTHROPIC_DEFAULT_HAIKU_MODEL` | `claudeCode.tierModels.haiku ?? claudeCode.smallFastModel` (опційно; також застаріле `ANTHROPIC_SMALL_FAST_MODEL`) |
| `ANTHROPIC_DEFAULT_{OPUS,SONNET,FABLE}_MODEL` | `claudeCode.tierModels.*` (опційно) |
| `CLAUDE_CODE_ALWAYS_ENABLE_EFFORT` | `1` коли `alwaysEnableEffort` увімкнено (умовно) |
| `CLAUDE_CODE_MAX_CONTEXT_TOKENS` / `DISABLE_COMPACT` | Застаріле перевизначення контексту, коли задано `maxContextTokens` (умовно) |
Змінні, які ви експортуєте самі, завжди мають пріоритет. Додаткові аргументи проходять наскрізь:
`ocx claude -p "hello"`.

## Інтеграція із системним середовищем (macOS)

Коли `claudeCode.systemEnv` встановлено в `true` (за замовчуванням: **вимкнено**), `ocx start`
використовує `launchctl setenv`, щоб впровадити `ANTHROPIC_BASE_URL` та пов'язані змінні середовища
Claude Code системно. Тому нові вікна й вкладки терміналів маршрутизують звичайні команди `claude`
через проксі без потреби в обгортці `ocx claude`. Уже відкриті оболонки не зачіпаються й мають бути
перевідкриті.

`ocx stop` та вимкнення проксі **скидають впроваджені ключі** (воно не відновлює попередні значення —
вилучаються лише ключі, які впровадив opencodex). Проксі також записує `~/.opencodex/claude-env.sh`;
`ocx start` встановлює source-хук у `.zshrc`, що завантажує його автоматично.

Вимкніть через `claudeCode.systemEnv: false` у конфігурації або перемикачем GUI. Ця функція лише для
macOS; на інших платформах використовуйте `ocx claude`.

## Нативна наскрізна передача Claude (пробій підписки)

Без заданого перевизначення автентифікації Claude Code зберігає свій OAuth-вхід claude.ai і надсилає
його до проксі. Запити на справжні моделі `claude*`/`anthropic*`, яких не заявляє жоден аліас чи мапа
моделей, перенаправляються **дослівно** до `api.anthropic.com` із вашими обліковими даними — бети,
сигнатури мислення, кешування промптів та платіжна ідентичність залишаються цілком нативними, а
маршрутизовані моделі продовжують працювати в тій самій сесії через аліаси селектора.

**Обробка заголовків:** hop-by-hop заголовки плюс `host`, `content-length`, `accept-encoding`,
`x-opencodex-api-key` та `origin` прибираються перед перенаправленням. Усі інші заголовки (зокрема
`anthropic-beta` та `anthropic-version`) проходять наскрізь.

Наскрізна передача спрацьовує, коли виконано **всі чотири** умови: `nativePassthrough` не `false`;
модель починається з `claude` або `anthropic`; bearer чи `x-api-key` починається з `sk-ant-`; а
розв'язання аліаса/мапи моделей повертає ту саму модель без змін. Це також означає, що попередження
«claude.ai connectors are disabled» більше не з'являється з `ocx claude`.

Вимкніть через `claudeCode.nativePassthrough: false`; спрямуйте кудись інде через
`claudeCode.anthropicBaseUrl`.

## Селектор /model («From gateway»)

Claude Code 2.1.129+ виявляє моделі шлюзу через `GET /v1/models?limit=1000` і перелічує їх у нативному
селекторі `/model` з міткою «From gateway». Оскільки селектор приймає лише ідентифікатори, що
починаються з `claude` чи `anthropic`, opencodex показує маршрутизовані моделі як стабільні, оборотні
аліаси:

| Інтерфейс | Формат | Приклад |
| --- | --- | --- |
| Claude Code CLI | `claude-ocx-<provider>--<model>` | `claude-ocx-native--gpt-5.6-sol` |
| Claude Desktop 3P | `claude-opus-4-8-<code>` (3-символьний base36-хеш) | `claude-opus-4-8-ncb` |

Проксі вибирає родину на кожен запит: `?ids=cli` або `?ids=desktop` перемагає; інакше user-agent
`claude-code/*` отримує читабельну CLI-форму, а інші клієнти — Desktop-хеш. Обидві родини декодуються
назавжди — модель, збережена в `settings.json` у будь-якій формі, продовжує працювати.

**Правила граматики аліасів:** провайдер не повинен містити `/` чи `--` й не дорівнювати `native`;
модель не повинна містити `/`. Маршрути, які читабельна форма не може виразити, відкочуються до
хешованого аліаса. Ідентифікатори моделей МОЖУТЬ містити `--` (розв'язання ділить лише за першим `--`);
нативні slug-и, що містять `--`, відкочуються до хешованої форми.

**Порядок розв'язання моделі:** маркер `[1m]` прибрано → читабельний аліас декодовано → Desktop-хешований
аліас декодовано → точний збіг `modelMap` → збіг із прибраною датою (видалено `-20250514`) → наскрізна
передача.

Кожен запис несе відображувану назву, як-от `gemini-3-pro (gemini)`, плюс повні можливості моделі
(драбина зусилля міркувань, типи мислення) в офіційній формі `ModelInfo`. Справжні моделі Anthropic
зберігають свої канонічні ідентифікатори на обох інтерфейсах.

### Контекстний варіант із маркером `[1m]`

Моделі з авторитетним вікном контексту 1M (або, за auto-context, понад 200k та щонайменше порога
компакції) отримують додатковий рядок селектора `…[1m]`. Його вибір змушує Claude Code рахувати повний
контекст 1M. Проксі прибирає нечутливий до регістру суфікс `[1m]` перед розв'язанням аліаса й
маршрутизацією.

## Auto context (моделі з великим контекстом без стелі 200k)

Claude Code рахує 200k токенів для будь-якої моделі, яку не розпізнає. **Auto context** (увімкнено за
замовчуванням) виправляє це:

1. Моделі, чиє справжнє вікно понад 200k **та** щонайменше порога автокомпакції, отримують маркер
   `[1m]` на своїх рядках селектора та слотах середовища.
2. `CLAUDE_CODE_AUTO_COMPACT_WINDOW` (за замовчуванням `350000`, діапазон `100000`–`1000000`)
   впроваджується, тож розмова автоматично підсумовується в цій точці.

Три стани конфіга:

- **відсутній / `true`:** увімкнено (за замовчуванням)
- **`false`:** вимкнено — без маркерів, без впровадження вікна компакції
- **задано застаріле `maxContextTokens`:** auto-context неявно вимкнено

Значення компакції регулюється на сторінці Claude. **Попередження:** підняття його понад справжнє вікно
моделі ламає цю модель — чат видає помилку до того, як підсумок зможе спрацювати.

Нативні моделі Anthropic до 1M ніколи не позначаються автоматично. Значення, які ви експортуєте самі,
завжди мають пріоритет (проксі використовує ВАШЕ значення, щоб вирішити, які моделі безпечно
позначати). Невалідні відредаговані вручну значення конфіга відкочуються до 350k.

### Ефективне середовище моделі

`effectiveModelEnv` обчислює шість слотів, впроваджуваних `ocx claude` / системним середовищем / файлом
оболонки: `ANTHROPIC_MODEL`, чотири `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU,FABLE}_MODEL` та застарілий
`ANTHROPIC_SMALL_FAST_MODEL`. Ефективний Haiku — це `tierModels.haiku ?? smallFastModel`, поданий до
обох змінних Haiku.

## Агенти ростера (injectAgents)

`ocx claude` (та демон системного середовища) синхронізує ваш ростер виведених субагентів (вкладка
Subagents, до 5 моделей) плюс `ocx-self` у `~/.claude/agents/ocx-*.md`.

- **`ocx-self`** пінує ваш дефолт селектора `/model` (відкочуючись до `claudeCode.model`); опускається,
  коли жодного не існує. Він НЕ використовує успадкування моделі.
- Тіло кожного агента містить директиву `<!-- ocx-route: <model> -->` — проксі використовує її, щоб
  запінувати справжній маршрут. Тому аргумент `model` інструмента Agent інертний; передавайте `"haiku"`
  як плейсхолдер.
- Frontmatter несе аліас; маршрутизація керується директивою.
- Перезаписуються чи вилучаються лише перевірені за маркером файли `ocx-*.md`, що містять
  `generated-by: opencodex`; ваші власні агенти ніколи не чіпаються.
- Файли синхронізуються атомарно на кожен файл (запис + перейменування).
- `enabled: false` або `injectAgents: false` вилучає всі перевірені визначення, що належать opencodex.
- PUT з GUI та зміни ростера синхронізуються негайно; лаунчер/системне середовище синхронізуються під
  час запуску.

Диспетчеризація: `subagent_type: "ocx-gpt-5-6-sol"`. Цілі, здатні до 1M, несуть `[1m]` автоматично.

## Елізія вбудованих скілів (blockedSkills)

Вбудований скіл Claude Code `claude-api` впроваджує ~840КБ (~136k токенів) документації Anthropic, що
автотригериться на згадках моделей Claude. Маршрутизовані моделі не навчені на цьому наборі, тож за
замовчуванням opencodex замінює вміст скіла коротким заглушником на **маршрутизованих** запитах. Нативна
наскрізна передача Anthropic не зачіпається.

**Обробляються два носії:**

1. **Носій результату інструмента:** виклики `Skill(...)` асистента — парне тіло `tool_result`
   замінюється заглушником, коли зменшений до нижнього регістру JSON-ввід містить заблоковане ім'я.
2. **Носій текстового блока:** текстовий блок користувача ≥10 000 символів, що починається з
   `Base directory for this skill: ` — збігається, коли basename директорії дорівнює заблокованому імені
   (нечутливо до регістру).

Налаштуйте через `claudeCode.blockedSkills` (за замовчуванням `["claude-api"]`; `[]` цілком вимикає
елізію). Заглушник зберігає парність виклик/результат інструмента цілою.

## Мапа моделей (перехоплення)

`claudeCode.modelMap` переписує вхідні ідентифікатори моделей Anthropic перед маршрутизацією:

```json
{
  "claudeCode": {
    "modelMap": {
      "claude-sonnet-4-5": "gemini/gemini-3-pro",
      "claude-haiku-4-5": "gemini/gemini-3-flash"
    }
  }
}
```

Порядок пошуку: аліас виявлення → точний ідентифікатор → ідентифікатор із прибраним суфіксом дати
(`-20250514`) → наскрізна передача.

## Матриця sidecar-ів: вебпошук і розуміння зображень

Не всі маршрутизовані моделі мають ті самі хостовані інструменти чи підтримку зображень. opencodex
заповнює ці прогалини перед тим, як основна модель відповість:

- **Sidecar вебпошуку** запускає справжній хостований пошук, потім дає маршрутизованій моделі відповідь
  і джерела як результат інструмента.
- **Sidecar зору** описує додане зображення перед викликом моделі, перелаченої в `noVisionModels`, потім
  замінює зображення цим описом.

Обидва sidecar-и можуть використовувати будь-який бекенд:

| Бекенд | Як працює | Що потребує |
| --- | --- | --- |
| `openai` | Невелика модель GPT через провайдера ChatGPT `forward` | Вхід у ChatGPT та ввімкнений провайдер `authMode: "forward"` |
| `anthropic` | Claude через збережений Anthropic OAuth; вебпошук використовує `web_search_20250305`, а зір надсилає зображення до Claude для опису | Ввімкнений провайдер `adapter: "anthropic"`, `authMode: "oauth"`, чий активний збережений акаунт не позначено `needsReauth` |

Явний `backend` завжди перемагає. Коли його опущено, opencodex вибирає `anthropic`, якщо існує придатний
збережений акаунт Anthropic OAuth; інакше вибирає `openai`. Явний вибір `anthropic` без придатних
облікових даних **падає закрито**: opencodex не позичає тихо облікові дані ChatGPT і не перемикає
бекенди. Бекенд OpenAI так само залишається вимкненим без і автентифікації входу, і провайдера forward.

Маршрутизовані повтори з вхідним Claude приєднують основний вхід ChatGPT до внутрішнього запиту, тож
sidecar-и OpenAI залишаються досяжними, навіть попри те, що вхідний bearer Claude Code — це лише
облікові дані проксі. Цей bearer ніколи не перенаправляється до маршрутизованого основного провайдера.

```json
{
  "webSearchSidecar": {
    "backend": "anthropic",
    "model": "claude-sonnet-5",
    "maxSearchesPerTurn": 3
  },
  "visionSidecar": {
    "backend": "anthropic",
    "model": "claude-sonnet-5",
    "maxDescriptionsPerTurn": 8
  }
}
```

`maxDescriptionsPerTurn` обмежує нові описи зображень в одному ході основної моделі. Влучання в кеш та
дублікатні описи в польоті не витрачають обмеження. Успішні описи для `data:`-зображень кешуються за
бекендом, моделлю, деталізацією, байтами зображення й контекстом запиту, тож та сама пара
зображення-й-контекст не описується знову на кожному повторі. Віддалені `https:`-зображення ніколи не
кешуються, бо їхній вміст може змінюватися.

Див. [Довідник конфігурації](/opencodex/uk/reference/configuration/#sidecars) щодо кожного ключа.
Вебпошук через Anthropic-OAuth та опис зображень повторно використовують наявний у репозиторії прецедент
OAuth-фінгерпринта Claude Code, але їх усе одно варто протестувати під навантаженням із вашим акаунтом і
навантаженням, перш ніж покладатися на них для довгих сесій без нагляду.

## Зусилля міркувань

Налаштування `/effort` у Claude Code зберігається через адаптер:

| Мережевий формат | Відображення |
| --- | --- |
| `thinking.type: "adaptive"` + `output_config.effort` | Зусилля передається напряму (`minimal`\|`low`\|`medium`\|`high`\|`xhigh`\|`max`\|`ultra`) |
| `thinking.type: "enabled"` + `budget_tokens` | ≤4096→`low`, ≤16384→`medium`, вище→`high` |
| `thinking.type: "disabled"` | Параметри міркувань цілком опущено |

Розв'язане значення з'являється в стовпці **Reasoning effort** журналу запитів.

## Вхідний переклад (Messages → Responses)

Проксі перекладає кожен запит Anthropic Messages API у формат Codex Responses API:

| Ввід Messages | Вивід Responses |
| --- | --- |
| Верхньорівневий `system` | `instructions` (текстові блоки з'єднано через `\n\n`) |
| `messages[].role: "system"` | Також згорнуто в `instructions` |
| Текст / зображення користувача | `input_text` / `input_image` (base64 → data URL) |
| Текст асистента | `output_text` |
| `tool_use` асистента | `function_call` (`input` → JSON-серіалізовані `arguments`) |
| `tool_result` користувача | `function_call_output` (`is_error` → префікс `[tool error]`) |
| Повтор `thinking` / `redacted_thinking` | Відкинуто |
| Функціональні інструменти | `{type: "function"}` (`web_search*` → `{type: "web_search"}`) |
| `tool_choice` | `auto`→`auto`, `none`→`none`, `any`→`required`, іменований→`{type:"function",name}` |
| `max_tokens` | `max_output_tokens` |
| `stop_sequences` | `stop` |

**Випадки помилок (400):** зламаний JSON; відсутній/порожній `model`; відсутні/порожні `messages`;
непідтримувана роль; `tool_result` без `tool_use_id`; `tool_use` без id/name; іменований `tool_choice`
без name.

## Вихідний переклад (Responses → Messages SSE)

| Подія Responses | Messages SSE |
| --- | --- |
| `response.created` | `message_start` + `ping` |
| Heartbeat | `ping` |
| Дельти тексту | `content_block_start` → `content_block_delta` (text) → `content_block_stop` |
| Резюме/текст міркувань | Блок `thinking` із синтетичною сигнатурою |
| Кадри виклику функції | Блок `tool_use` із `input_json_delta` |
| Термінальна подія | `message_delta` → `message_stop` |
| EOF до термінальної | `api_error` у стилі 502 |

**Відображення причини зупинки:** `completed` → `tool_use` (якщо є виклик інструмента) або `end_turn`;
`incomplete/max_output_tokens` → `max_tokens`; `incomplete/content_filter` → `refusal`.

**Таксономія помилок:** 400 `invalid_request_error`, 401 `authentication_error`, 402 `billing_error`,
403 `permission_error`, 404 `not_found_error`, 409 `conflict_error`, 413 `request_too_large`,
429 `rate_limit_error`, 504 `timeout_error`, 529 `overloaded_error`, інші 5xx `api_error`. `Retry-After`
зберігається.

## Кешування промптів та використання токенів

**Запити, маршрутизовані до Anthropic:** адаптер керує брейкпоінтами кешу для інструментів, системного
вмісту та передостаннього повідомлення користувача, плюс верхньорівневий автоматичний `cache_control`.
Стабільні ходи зазвичай дають близько 99,9% влучань у кеш.

**Нативна маршрутизація OpenAI/ChatGPT:** виводить `prompt_cache_key` в межах сесії (з
`metadata.user_id`, коли присутній, відкочуючись до хешу системного вмісту) та заголовок `session_id`
для афінності кешу. Ключ кешу включає модель та повні схеми інструментів.

**Математика токенів:** вивід Anthropic віднімає `cached_tokens` та `cache_write_tokens` від
`input_tokens`, показуючи їх як `cache_read_input_tokens` та `cache_creation_input_tokens`. Журнали
запитів відображають їх назад на включний `inputTokens`, з читаннями і в `cachedInputTokens`, і в
`cacheReadInputTokens`, записами в `cacheCreationInputTokens`. Сторінка Usage повідомляє влучання в кеш
та створення кешу окремо.

**count_tokens:** маршрутизовані моделі використовують наближення (серіалізовані system + messages +
tools). Нативні моделі Anthropic з обліковими даними `sk-ant-` передають запит наскрізь до справжнього
ендпоінта Anthropic `/v1/messages/count_tokens`.

## Захоплення для налагодження

`ocx debug claude on|off|status|reset`, `OCX_CLAUDE_DEBUG=1` або `PUT /api/debug {"claude": true}`
керує вхідним захопленням. `GET /api/claude/inbound-debug` повертає `{enabled, entries}` (найновіші
першими, кільце з 20).

Кожен запис фіксує: `at`, `endpoint`, `model`, `resolvedModel`, `stream`, `maxTokens`, `thinkingType`,
`thinkingBudgetTokens`, `outputConfigEffort`, `metadataKeys`, `hasMetadataUserId`, `hasSystem`, сирий
`anthropicBeta` та восьмисимвольні теги рівності HMAC для user id / system. **Жоден текст промпту, сирий
об'єкт чи стабільний міжзапусковий хеш не зберігається.** Вимкнення налагодження Claude негайно очищає
кільце.

## GUI (сторінка Claude)

Бічна панель має окрему сторінку **Claude** (нижче API) та перемикач **Claude ON** (мітка навмисно
ідентична в кожній мові). Сторінка показує:

- Аварійний вимикач вхідного (перемикач enabled)
- Швидкий старт (`ocx claude`) та блок ручного середовища
- Селектор Fast Mode (Auto / ON / OFF)
- Перемикач auto-context та випадний список порога компакції
- Перемикач автореєстрації субагентів
- Редактор перехоплення моделей (modelMap)
- Живий попередній перегляд аліасів селектора

`GET /api/claude-code` повертає ефективні дефолти, конфіг, реєстр вікон контексту, ефективне середовище,
доступні ідентифікатори маршрутів, аліаси та порт. `PUT /api/claude-code` частковий і зберігає опущені
поля; `null` скидає значення контексту/блоклиста/вікна компакції.

## Усунення проблем

**Claude Code каже «Did 0 searches»** — Поточні збірки перекладають завершені елементи Responses
`web_search_call` у парні блоки Anthropic `server_tool_use` та `web_search_tool_result`, зокрема
`usage.server_tool_use.web_search_requests`. Оновіть opencodex, якщо старіша збірка завершила пошук, але
Claude Code усе одно нарахував нуль.

**Sidecar не активується** — Для `backend: "openai"` переконайтеся, що ви ввійшли в ChatGPT і маєте
ввімкнений провайдер `authMode: "forward"`. Для `backend: "anthropic"` переконайтеся, що активний
збережений акаунт Anthropic OAuth не позначено `needsReauth`. Явний вибір Anthropic без цих облікових
даних навмисно падає закрито.

**«claude.ai connectors are disabled»** — У вашій оболонці встановлено `ANTHROPIC_API_KEY` або
`ANTHROPIC_AUTH_TOKEN`. `ocx claude` навмисно НЕ встановлює `ANTHROPIC_API_KEY`; якщо він у вас
експортований, скиньте його. `ocx claude` впроваджує `ANTHROPIC_BASE_URL`, виявлення, auto-context та
налаштовані слоти моделей — але ніколи `ANTHROPIC_API_KEY`.

**Моделі не показуються в селекторі /model** — Переконайтеся, що встановлено
`CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` (автоматично з `ocx claude`). Запустіть `ocx claude`, щоб
оновити кеш моделей шлюзу в `~/.claude/cache/gateway-models.json`. Перевірте, що `claudeCode.enabled` не
`false`.

**Застаріле середовище після зміни порту** — Якщо порт проксі змінився, старі оболонки можуть мати
застарілий `ANTHROPIC_BASE_URL`. Відкрийте новий термінал або повторно запустіть `ocx claude`.

**Стеля контексту 200k попри велику модель** — Виберіть варіант `[1m]` у селекторі або ввімкніть
auto-context (увімкнено за замовчуванням). Якщо селектор не показує рядка `[1m]`, авторитетне вікно
контексту моделі може бути нижчим за поріг автокомпакції.

**Висока кількість токенів від завантаження скілів** — Вбудований скіл `claude-api` (~136k токенів)
автозавантажується на згадках моделей Claude. Це нормально для нативної наскрізної передачі; на
маршрутизованих моделях opencodex заглушує його за замовчуванням (`blockedSkills: ["claude-api"]`).

**Субагент диспетчеризується до неправильної моделі** — Агенти ростера (`ocx-*`) використовують
директиви `<!-- ocx-route: ... -->`, а не аргумент `model` інструмента Agent. Переконайтеся, що
директива відповідає призначеному маршруту. Передавайте `"haiku"` як плейсхолдер моделі.
