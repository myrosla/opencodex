---

Коли Codex запитує модель, `router.ts` зіставляє її рівно з одним налаштованим провайдером. Правила
перевіряються **по порядку**; перемагає перший збіг.

Для OpenAI звичайні ідентифікатори `gpt-*` вибирають один провайдер `openai`. Його `codexAccountMode`
обирає Pool (за замовчуванням, основний плюс додані акаунти) або Direct (bearer поточного викликача /
основного входу) без зміни ідентифікатора моделі. `openai-apikey/<model>` явно вибирає транспорт із
API-ключем. Два облікові маршрути не перетікають один в одного.

## Пріоритет

1. **Явний `provider/model`** — якщо ідентифікатор містить `/`, а частина перед ним є ім'ям
   налаштованого провайдера, використовується цей провайдер, а ідентифікатор скорочується до частини
   після слеша.

   ```text
   anthropic/claude-opus-5     →  провайдер "anthropic",   модель "claude-opus-5"
   ollama-cloud/glm-5.2        →  провайдер "ollama-cloud", модель "glm-5.2"
   openrouter/openai/gpt-5.6-sol → провайдер "openrouter",  модель "openai/gpt-5.6-sol"
   ```

   Це однозначна форма, і саме її використовує селектор моделей Codex для маршрутизованих моделей.
   Якщо названий провайдер вимкнено, ця явна форма викидає помилку замість маршрутизації.

2. **`defaultModel` провайдера** — якщо `defaultModel` будь-якого провайдера дорівнює ідентифікатору,
   використовується цей провайдер (ідентифікатор передається без змін).

3. **Вбудовані шаблони префіксів** — ідентифікатор зіставляється з відомими префіксами родин моделей,
   після чого маршрутизується до налаштованого провайдера з цим ім'ям (або префіксом імені):

   | Префікси | Провайдер |
   | --- | --- |
   | `claude-`, `claude-sonnet-`, `claude-opus-`, `claude-haiku-` | `anthropic` |
   | `gpt-`, `o1-`, `o3-`, `o4-` | звичайні ідентифікатори використовують налаштований режим акаунта `openai`; для транспорту з API-ключем використовуйте `openai-apikey/` |
   | `llama-`, `mixtral-`, `gemma-` | `groq` |

   Цей зіставник базується на імені й, на відміну від сканувань `defaultModel` / `models[]`, наразі не
   відфільтровує провайдера-збіг, чий прапорець `disabled` встановлено в true.

4. **`models[]` провайдера** — якщо жодне правило префікса не перемогло й активний провайдер перелічує
   ідентифікатор у своєму `models[]`, використовується цей провайдер. Цей порядок важливий: за
   наявності налаштованого провайдера з ім'ям OpenAI звичайний ідентифікатор `gpt-*` досягає його
   раніше, ніж заявки `models[]` іншого провайдера.

5. **Провайдер за замовчуванням** — якщо нічого не збіглося, ідентифікатор надсилається до
   `config.defaultProvider` без змін. (Якщо провайдера за замовчуванням не налаштовано або його
   вимкнено, маршрутизація викидає помилку.)

## API-ключі та змінні середовища

Хоч який маршрут вибрано, `apiKey` провайдера розв'язується через `resolveEnvValue()`: значення
`${OPENAI_API_KEY}` або `$OPENAI_API_KEY` розгортається із середовища під час запиту, тож секрети
ніколи не повинні жити в `config.json`.

## Видимість у каталозі та обмеження контексту

Маршрутизація й видимість у каталозі — це окремі елементи керування:

- `disabledModels` приховує маршрутизовані ідентифікатори з простором імен із каталогу Codex та
  `/v1/models`; звичайний нативний GPT-slug залишається в каталозі з `visibility: "hide"`. Це **не**
  відхиляє прямий запит до цієї моделі.
- Непорожній `selectedModels` провайдера — це ще один allowlist каталогу. Живе виявлення й пряма
  маршрутизація все одно працюють; звужується лише випуск каталогу та `/v1/models`.
- `provider.disabled: true` вилучає цього провайдера з виявлення каталогу. Явні запити `provider/model`
  зазнають невдачі, а сканування `defaultModel` / `models[]` його пропускають.
- `providerContextCaps` застосовує видимі в Codex обмеження контексту для кожного провайдера.
  `contextCapValue` — це спільне значення панелі (350 000 за замовчуванням), але саме по собі воно
  нічого не робить, доки провайдер не присутній у `providerContextCaps`. Обмеження лише знижують відоме
  вікно контексту; вони ніколи не піднімають його й не змінюють фактичного ліміту вихідної моделі.

```json
{
  "contextCapValue": 350000,
  "providerContextCaps": {
    "anthropic": 350000,
    "cursor": 350000
  }
}
```

## Поради

- **Будьте явними для маршрутизованих моделей.** Віддавайте перевагу `provider/model` (правило 1) — це
  однозначно й відповідає тому, що Codex показує в селекторі після синхронізації каталогу.
- **Задайте `models[]` або `defaultModel`** на провайдері, щоб короткі ідентифікатори (правило 2/4)
  розв'язувалися без префікса `provider/`.
- **Шаблони префіксів — це зручність**, а не гарантія: вони розв'язуються лише тоді, коли провайдер із
  цим ім'ям (наприклад, `anthropic`, `openai`, `groq`) справді налаштований.

Див. [Конфігурацію](/opencodex/uk/reference/configuration/) щодо полів провайдера, які читають ці
правила.
